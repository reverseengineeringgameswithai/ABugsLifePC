# EXP-20260813-054 - M2 continuation scope disposition

## Question

After M2.38 retires the only selected finite dependency candidate, should M2
close, continue through an unranked dependency search, or defer its unchanged
causal gate while already proven mod capabilities advance?

## Scope and procedure

This packet reviewed only existing evidence for executable SHA-256
`97c95ba5572dce637f6ea6325dbfff0c9a2d002a30d3dc88f39e0f558a27b878`:

- `EXP-20260813-049`'s four-gate M2 audit;
- `EXP-20260813-052`'s decision that the parallel M1 and ID-zero rendered
  chains cannot be merged without weakening the causal milestone outcome;
- `EXP-20260813-053`'s complete negative for the sole ranked signed-selector
  candidate;
- the accepted, asset-free exact whole-file replacement recipe from
  `EXP-20260812-033/049`; and
- the existing hash-guarded manifest/staging boundary in
  [[M1 Tool Support Matrix]].

The roadmap's status definitions, M3 entry condition, M4 incremental-
accumulation text, north-star outcomes, and exact M4 capabilities were then
reconciled. No executable or game asset was opened for new analysis. No game
was launched or instrumented. No source, target, parser, manifest schema, or
runtime tool was modified. No new index/resource family, whole-program
indirect search, semantic name, or PS1 evidence was introduced.

## Disposition

M2 cannot close. The first exit gate still requires one reviewable causal path
from a level placement/positive target through a selected external resource to
a rendered or behavioral outcome. `EXP-20260813-049/052/053` leave that exact
edge unsupported. Calling the two separately proven rendered chains one path
would repeat the gate weakening rejected by M2.37.

M2 also should not remain nominally active without a work packet. The complete
direct-reader, selector-2 input, generic-index, and signed-selector negatives
leave no ranked finite PC-native candidate. Continuing into a new index or
resource family would be an open-ended strategy change, not evidence-driven
continuation from M2.38. Persistent/copied state remains unknown, but a
possibility is not a producer or a bounded discriminator.

The roadmap's `Blocked` status is not appropriate because no named external
dependency prevents all meaningful project progress. `Deferred` preserves the
unsatisfied gate and makes its revisit condition explicit without pretending
that M2 is complete. M3 remains planned because its current entry condition
requires the missing M1-M2 resource/placement bridge.

M4 can advance independently at its already written incremental boundary.
The repository has one promoted M1 manifest edit family and one accepted exact
whole-file resource replacement whose instructions can be distributed without
either asset. The smallest successor is therefore M4.1: add a versioned,
fail-closed whole-file replacement manifest boundary for user-owned work-copy
files, guarded by exact source and destination hashes and integrated with the
existing non-destructive staging/receipt flow. This does not imply a `.ALL`
parser, general file compatibility, filename identity, or permission to
bundle game bytes.

## Confirmed

- `KU-023` and M2's first exit gate remain unresolved after the exact
  `EXP-20260813-049/052/053` evidence chain.
- M2.38 retired the only selected finite candidate and did not authorize a
  successor family.
- Existing tooling supports exact-hash M1 edits, sparse/staged output, and
  receipts; `EXP-20260812-033/049` separately supports one exact asset-free
  whole-file replacement recipe.
- The roadmap explicitly permits M4 capabilities to accumulate from proven
  earlier work; M3's entry condition still requires the missing bridge.

## Inferred

Prioritizing the bounded whole-file manifest operation is the best current
use of the proven resource result because it converts accepted evidence into
reversible user value without manufacturing the missing causal edge. This is
a roadmap prioritization inference, not new evidence about `.ALL` contents or
resource identity.

## Unknown and limitations

- The exact M1 placement/positive-target-to-resource selection edge remains
  unknown under `KU-023`.
- Persistent/copied cross-frame state and unranked indirect aliases remain
  outside the completed finite searches.
- General `.ALL` layout, compatibility, semantics, and filename identity are
  unknown.
- M4.1 is selected but not implemented by this evidence-only packet.

## Contradictions and negative results

M2 is not complete, and it is not externally blocked. Keeping it `Active`
without an exact packet would contradict the roadmap's single-work-packet
rule; marking it `Complete` would contradict its first exit gate. `Deferred`
is the status that preserves both facts.

## Result and follow-up

M2.39 is complete as a scope disposition. M2 moves to `Deferred` with its
causal gate unchanged and `KU-023` unresolved. Revisit it only when a new
finite PC-native candidate is justified by cited evidence, a concrete mod goal
requires the bridge and supplies a bounded discriminator, or contradictory PC
evidence invalidates a completed negative.

M4 becomes the active milestone. M4.1 must remain limited to an exact-hash,
user-owned whole-file replacement manifest operation plus synthetic safety,
locality, receipt, and staging tests. It must not bundle assets, generalize
`.ALL` compatibility, add format semantics, launch the game, or consult PS1.
