## Sole successor: M4.28

**Name:** Strict receipt reconstruction for replay and removal.

**Bounded question:** Can one byte-exact ordinary current receipt, together
with the exact source root it names by hash, reconstruct one strict existing-
schema manifest and reproduce or remove the same dedicated sparse overlay,
without the original manifest and without changing receipt bytes, schemas,
formats, operations, guards, or accepted workflow semantics?

**Exact locators:** `_receipt_for`, `_receipt_bytes`, `_parse_receipt`,
`_validate_manifest`, `_prepare_manifest`, `apply_manifest`, and
`remove_manifest` in `reimplementation/ablpc/manifest.py`; command construction
and error handling in `reimplementation/ablpc/cli.py`; receipt/application/
removal tests in `tests/test_manifest.py` and `tests/test_level_dat.py`; the
receipt-sufficiency capability above; [[M1 Tool Support Matrix]]; [[M4 Exact Whole-file Replacement]]; and `reimplementation/README.md`.

**First pass:** add one strict receipt loader and one receipt-to-current-
manifest reconstruction path. Require exact root/file/edit fields, current
schema/operation combinations, authored contiguous `edit_index` values, safe
unique paths, lowercase exact hashes, and ordinary byte encoding. Infer only
the already unique current format from the current operation family. Add
bounded CLI entry points that (1) replay the receipt into a dedicated sparse
overlay from the exact source and require the newly computed receipt to match
byte-for-byte before success, and (2) remove that exact overlay using the same
external receipt and source without the original manifest. Reuse ordinary
preparation, topology preflight, writing, receipt equality, and removal rather
than creating parallel edit semantics. Cover schemas 1/2, all four operations,
multi-file/composed receipts, wrong source/output, malformed/forged/reordered/
duplicate/unknown receipt fields, unsafe or aliased paths, nonregular inputs,
later failure, deterministic bytes, and exact source/overlay snapshots.

**Stop rule:** do not change the receipt, manifest, report, or compatibility-
statement schemas; add an operation or format; embed game bytes or whole
outputs; accept legacy/arbitrary receipts; weaken manifest/source/hash/guard/
path/topology checks; remove staged trees or source files; add launch, package,
backup, trash, rollback, transaction, N-way, general dry-run, `.ALL`, runtime,
M2, or PS1 behavior. Do not infer that M4 or the separate clean-copy lifecycle
gate is complete.

**Done when:** one external ordinary receipt plus exact source reproduces byte-
identical sparse outputs and the exact ordinary receipt without the original
manifest; the same receipt/source removes only that authenticated overlay;
every malformed, ambiguous, forged, mismatched, unsafe, nonregular, and later-
failure case refuses before mutation with exact snapshots; all existing
manifest-driven workflows and receipts remain byte-identical; compatibility
pins and nine-read scope are refreshed only as required; all asset-free and
tracked local gates pass; one clean worker commit is ready for fresh-context
hard-truth review.
