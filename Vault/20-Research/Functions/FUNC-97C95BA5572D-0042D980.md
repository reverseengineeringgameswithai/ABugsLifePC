# Function 0x0042D980

## Summary

Walks all 16 event slots and calls the `+0x08` callback of each one that is in
use. `+0x08` is left unnamed: unlike `+0x04` and `+0x0C`, no log string in the
binary describes it.

**Extent:** `0x0042D980`-`0x0042D9B3` (file `0x02CD80`-`0x02CDB3`). One `ret`,
at `0x0042D9B3`, followed by `nop` then `int3` padding. Every direct branch
inside the range was enumerated; none leaves it.

## Confirmed

- `esi = 0x005982B8` (record 0 `+0x08`), `edi = 0x10`, step `+0x3C`
  (`0x0042D983`-`0x0042D9AB`).
- Tests `[esi+0x2c]`, i.e. record `+0x34`, against `1` at `0x0042D992`.
- On a match, stores `esi-0x8` — the record base — to `0x005982AC` at
  `0x0042D99A`, then loads `[esi]` (record `+0x08`) and, if non-null, executes
  `call eax` at `0x0042D9A5`.
- Returns `ax = 1` unconditionally (`mov ax,bx` at `0x0042D9AE`, `bx = 1` from
  `0x0042D98D`).

`0x0042D9D0` performs the same operation for a single record given by pointer,
tail-jumping to `+0x08` at `0x0042D9E6`; its thunk `0x0040179E` has no callers.

## Later findings (2026-10-02 audit pointer)

Both callers now sit in functions that other notes characterise (call sites
rechecked by disassembly and `ghidra-query.py` on 2026-10-02):

- `0x00405CB0` is inside `0x00405BE0`, the frame-begin routine that stores the
  render timestamp at `0x00405C07` and is called from renderer `0x0044D430` at
  `0x0044D44A` ([[EXP-20260907-028 - Representative update and render headroom]])
  and from the InitLoadScreen loop
  (EXP-20261001-004).
- `0x0043DC5A` is inside `0x0043DA40`, the WinMain-like outer loop
  ([[EXP-20260816-143 - Automatic Direct3D startup static audit]]).
- So the pass probably runs once per rendered frame. That is inference from
  the call sites; no dispatch has been observed, and this function logs
  nothing.

## Later findings (2026-10-18)

- **What `+0x08` does.** It is the per-frame poll: for WINDOWS the Win32
  message pump `0x004AE780` (`PeekMessageA`, accelerators, dispatch, quit
  flag `0x0059F7C8`); for DIRECTX a no-op `0x0042BB30`.
- **The idle path.** The second caller runs it after `WaitMessage`
  (`0x0043DC54`).
- **Runtime.** No dispatch is logged, but both registrations appear in 574
  saved logs:
  [[EXP-20261018-005 - Event callbacks and registrations]].
