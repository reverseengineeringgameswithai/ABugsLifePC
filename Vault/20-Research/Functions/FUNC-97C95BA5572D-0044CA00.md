# Function 0x0044CA00

## Summary

Address-based function containing a bounded source-record loop that uses a
signed word to select a per-resource pointer and walks its associated
`0x50`-byte runtime-entry range. Its complete contract and semantics remain
unknown.

## Confirmed

- `0x0044CE0D` reads a signed selector from source-record-relative
  `[edi-0x08]` and `0x0044CE11` uses it to select a pointer from table
  `0x005B1A7C`.
- `0x0044CE18/0x0044CE1C` read signed start/end words from selected pointer
  offsets `+0x04/+0x06`.
- `0x0044CE20–0x0044CE2A` computes
  `0x005A9660 + start_index * 0x50`.
- `0x0044CE3E` reads the selected entry word at `+0x2E`; the following branch
  chain distinguishes values 1, 2, and 3.
- `0x0044D1D8–0x0044D1ED` advances the entry pointer by `0x50` and loops until
  the selected header's end index.
- `0x0044CA1F` initializes source cursor `EDI = 0x0059D9C8`;
  `0x0044D1F7` advances it by `0x30`, and
  `0x0044D1FB-0x0044D205` bounds at most 20 records. The signed selector
  words are exactly `0x0059D9C0 + i * 0x30` for `0 <= i < 20`.
- The header expression at `0x0044CE11` addresses exact ID-zero slot
  `0x005B18E0` if and only if the sign-extended selector is `-103`
  (`0xFF99` as a word), because
  `0x005B1A7C + (-103 * 4) == 0x005B18E0`. This proves addressability, not an
  observed selector or its producer (`EXP-20260813-052`).
- `EXP-20260813-053` classifies the exact selector writers. Four paths only
  clear to zero; sole nonzero writer `0x00467E60` copies one of 20 positive
  image-table words and has no `0xFF99` entry. Its normal-update call occurs
  before M1 coordinator entry and consumes a separate fixed `0x84`-stride
  pool. The M1/signed-`-103` candidate is therefore negative and retired.
- Plant 10's measured table slot is
  `0x005B1A7C + 10 * 4 == 0x005B1AA4`; its runtime value
  `0x006C342B` has start/end words `66/68` in
  `RUN-GDB-20260812-201419` ([[EXP-20260812-027 - Plant10 entry 28 bounded negative]]).
- In accepted `RUN-GDB-20260812-203714/203820`, neither exact plant 10
  `+0x2E` word produces an access stop from the natural title through
  `NextLife` or a separate 30.026628-second no-input gameplay arm. Exact
  execution breakpoint `0x0044CE3E` also records zero stops in a separate
  10.014330-second control ([[EXP-20260812-028 - Plant10 post-title selected-entry negative]]).
- Fresh simultaneous `RUN-GDB-20260812-211649` includes a hardware breakpoint
  at this entry but faults at outer gate `0x0044D79A` before any accepted entry
  continuation. Its zero entry-stop count is not a negative for this function
  ([[EXP-20260812-029 - Fresh selected-entry chain debugger fault]]).

## Inferred

This remains an event-specific static candidate for a resource entry consumer.
The exact instructions would select plant 10's measured entries 66 and 67 if
a source record supplies selector 10 at `[edi-0x08]`; they would instead
address the retained ID-zero header if the selector is `-103`. Neither
condition has been observed at runtime, and the candidate was inactive in
M2.15's accepted exact-reader control interval.

## Unknown

- Parameters, return value, complete caller set, and source-record structure.
- Whether a Training object supplies selector 10 after the title.
- Whether wider-lifetime copied state connects this separate selector array
  to another system; M2.38 finds no M1-derived signed `-103` producer at its
  declared current-invocation boundary.
- Meanings of entry `+0x2E` values and the downstream branches/callees.
- Whether any selected branch connects to an M1 placement or visible result.

## Later findings (2026-10-02 audit pointer)

- [[EXP-20260904-001 - Original PC lateral collision and descriptor-store probes]]
  (raw instructions, 27 synthetic branch cases, prefix run in Unicorn): the 20
  source records are the plant array `0x0059D9C0` (stride `0x30`). For a slot
  with nonzero type, a loaded resource header, flag `0x02` at `+0x2E` and a
  nonnegative template from `0x007F29E8 + 2*type`, the prefix writes collision
  descriptor `N+i` in table `0x007F4590` (N = `DWORD[0x007F3D30]`), tag
  `type+0x67`, at nine stores `0x0044CAA9`–`0x0044CB17`. This is the
  render-side collision mutation tracked as
  [[Known Unknowns#KU-081 - Render-side mutation of the collision descriptor table (FUN_0044ca00)|KU-081]];
  the whole function's side effects remain unproven.
- [[EXP-20260906-007 - Plant-state collision regression]] ([[PC seed and mushroom collision state]]):
  a type-5 plant in slot 2 registers descriptor 193 (N = 191), tag 108, from
  PLANTTER source 8, in failing and repaired runtime.
  [[EXP-20260909-004 - Restore native plant collision]]: `0x0044CA7F` skips the
  copy when the tag is unchanged, so cached bounds survive a live payload edit.
- EXP-20260914-013: a hardware arm faulted at
  `0x0044CA3B`. Rechecked in this audit, `0x0044CA24`–`0x0044CA3B` reads the
  slot's signed type word, loads `0x005B1A7C[type]` and dereferences it; PLANT03
  had not been loaded, so the pointer was null.
- So the source-record structure and selector producer are answered for this
  prefix (the plant type stored by `0x00467E60`). Selected-entry `+0x2E` values
  and the rendering branches remain unknown.
