# Function 0x004A7600

## Summary

Candidate renderer-choice screen called from `0x0043DA40` only when the
machine probe selected Direct3D candidate value 2. It creates temporary
DirectDraw state, defaults its interactive selection to native software,
returns selector 1 or 2, and performs its own display/surface cleanup.

## Confirmed

- Initializes display globals to 640x480x16, creates temporary DirectDraw
  surfaces, locks the back surface, and replaces the depth with a
  surface-derived 15/16-bit result before entering its input loop. Evidence:
  `EXP-20260816-143`, native instructions and Ghidra export at `0x004A7600`.
- Sets renderer selector `0x0059F7F0` to 1 during chooser setup and selection
  index `0x007F1150` to zero. Evidence: `EXP-20260816-143`, instructions
  before `0x004A786B`.
- Confirmation or the 60-second timeout sets the local result to
  `(index != 0) + 1`; therefore the untouched default is selector 1.
- The normal tail frees temporary image buffers, restores display mode,
  releases back/front/DirectDraw objects, copies the local result to
  `0x0059F7F0`, and maps result 1/2 back to the software/Direct3D flags.
- The exact paired transform in EXP-143 retains initialization through
  `0x004A7866` and resumes at cleanup `0x004A7A56`; it has not been run.

## Inferred

- The function is the visible software-versus-hardware choice screen logged
  as `SwitchDriverScreen`.
- Its temporary surface initialization is required startup state, so skipping
  the complete call is unsafe without further evidence.

## Unknown

- Fresh runtime behavior of the paired static auto-confirm candidate.
- Whether skipping the temporary pitch write has any observable effect on an
  actual Direct3D surface; later lock paths independently write the global.
- Complete meaning of every `0x00861Cxx`/`0x00861Dxx`/`0x00861Exx` display
  global.
