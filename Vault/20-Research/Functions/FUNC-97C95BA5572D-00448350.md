# Function 0x00448350

## Summary

Iterates a null-terminated pointer list rooted at `0x0059D7E0`. For each
pointed-to object, the first dword is used as a runtime index into header table
`0x005B18E0`. The object's and entry fields remain semantically unidentified.

## Confirmed

- The sole direct caller is M1 coordinator `0x0044D430`, which calls thunk
  `0x00401532` at `0x0044D4E6` when bit `0x10` of `0x005C5EDC` is clear.
- The list cursor begins at `0x0059D7E0`; native instructions
  `0x00448460-0x00448462` load the current object's first dword and form
  `0x005B18E0 + index * 4`. Later reads at `0x00448579`, `0x0044859B`,
  `0x004485B2`, `0x004485D1`, and `0x00448B28` reuse the same object index.
- The function reads header bounds, forms `0x005A9660 + entry_index * 0x50`,
  and dispatches entries according to exact offset tests. Those operations do
  not establish field or primitive semantics.
- The normal `0x0040FFC0` branch builds the object-pointer list earlier through
  `0x004144C0 -> 0x0041EC40`. List insertion at `0x0041ECF1` is guarded by a
  positive object-first-dword test at `0x0041EC6A-0x0041EC6E`.
- This function's call at `0x0044D4E6` precedes M1 record-root load
  `0x0044D4FA` and first record test `0x0044D57F`. The selected M1 record or
  payload in that invocation therefore does not produce this read's index
  (`EXP-20260813-051`).

## Inferred

That structural description does not identify the objects, header indices,
entries, or rendered output.
