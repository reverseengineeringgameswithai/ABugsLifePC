# Function 0x00444B70

## Summary

Relocates the first-level file offsets in a loaded `.ANM` buffer and, for its
first nonzero reference, exposes one signed-word list to shared runtime state.

## Confirmed

- Reads a signed 16-bit count at file-relative `+0x02` and walks that many
  dword offsets from `+0x08`. Evidence: `0x00444B7C–0x00444BA0`.
- Leaves zero entries unchanged and replaces every nonzero offset with
  `file_base + offset` in place. It retains the first nonzero result for the
  remainder of the function. Evidence: `0x00444B89–0x00444B99`.
- When that pointer and the second argument are nonzero, reads an unsigned
  16-bit count at first-record `+0x08`; the signed-word list begins at `+0x0C`.
  Evidence: `0x00444BA2–0x00444BC8`.
- Scans that list and distinguishes only signed value `-2` in this routine.
  Evidence: `0x00444BCE–0x00444C05`.
- Caller `0x00444C40` supplies flag 1 at call site `0x00444D21`, but first
  overwrites in-memory words `+0x00` and `+0x04`. The whole-file loader size
  controls arena advancement but is not passed to this function.
- All 11 local PC plant `.ANM` files pass the independent bounds-checked
  reproduction of this walk (`EXP-20260812-017`).

## Inferred

This is a first-level `.ANM` relocation/setup routine. Neither `ANM` nor a
semantic name appears in the function itself; the format association comes
from the exact caller path and `.anm` extension construction.

## Unknown

- Semantics of header words and nested record fields.
- Meanings of non-`-2` signed-list values and the resulting global tables.
- Layouts of referenced records other than the first nonzero one.
- Original malformed-file behavior beyond the fact that no byte-size argument
  bounds this function.

## Later findings (2026-10-02 audit pointer)

- [[EXP-20261001-002 - Flik animation catalog]] decodes the records this
  routine relocates, through pose sampler `0x00445FF0` (fresh disassembly):
  each nonzero first-level offset is one animation slot record. First-record
  `+0x08` is the part-list count and the `+0x0C` words are per-part word
  offsets into a frame (`-3` inherit, `-2`/`-1` skip). See
  [[PC ANM first-level]] (Slot records).
- This answers the first three Unknown items at the slot-record layer. With
  `+0x0A` as the bitmask length, 303 records in 60 of 61 retail `.ANM` files
  end with zero slack; `LEVEL00/ROSIEWLK.ANM` does not fit.
- Still open: what this routine's `-2` branch publishes, and the meanings of
  the linear, angle and extra words.
