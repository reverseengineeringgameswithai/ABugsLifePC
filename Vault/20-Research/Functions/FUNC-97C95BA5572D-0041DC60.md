# Function 0x0041DC60

## Summary

Interprets a per-slot word-code program for one record of the 64-slot pool at
`0x0059B628`. The program counter lives in slot `+0x70` and persists between
frames, so this is a resumable interpreter rather than a per-frame evaluator.

**Extent:** `0x0041DC60`-`0x0041E845`. Its only `ret` is at `0x0041E7D3`, but
`0x0041E7D4`-`0x0041E845` is entered from `0x0041E6CD`/`0x0041E6D8`, shares the
frame, and returns via `jmp 0x41e6e6` at `0x0041E841`. Everything below is
established for the fetch/dispatch half through `0x0041E1A8`; the region past
it — where the five modes selected at `0x0041E14F` are consumed, though what it
computes with them is **not analysed** — is enumerated only for `+0x5C`
accesses, `+0x70` writers, its indirect call and the record fields it
touches.

The proposed name is deliberately address-based. The mechanism — a resumable
16-bit-word interpreter over the `0x0059B628` pool — is what the instructions
show. The subsystem tag "creature-actors" comes from the executable's own
`LOAD: Type 35, CreatListRam.` string for the table that feeds that pool, and
is a label for the row, not a claim about what any program does.

## Confirmed

- Loads `ebp` from slot `+0x80` (the level-supplied source record) and `edi`
  from slot `+0x70` at `0x0041DC6D`-`0x0041DC73`.
- Decrements the wait counter `+0x60` at `0x0041DCCD` and runs the body only
  when it becomes negative (`jge 0x41E147`).
- Fetches a signed 16-bit opcode with `movsx eax,WORD PTR [edi]`, adds 1,
  rejects `> 0x19`, and dispatches through the 26-entry table at `0x0041E848`
  — opcodes `-1` through `24`.
- Ends the frame when a handler leaves the program counter unchanged, and
  steps it by one word if that happened on the frame's first instruction
  (`0x0041E131`-`0x0041E140`).
- Persists the program counter back to `+0x70` at `0x0041E147`. **Three**
  further writers of `+0x70` exist past that point, each reached only when the
  pending opcode is a blocking one: `0x0041E1EB` (`+2`, mode 2),
  `0x0041E2E1` (`+6`, pending opcode 17 or 18) and `0x0041E7FE` (`+2`, mode
  `> 2`). The `+6` case is not followed up.
- Invokes the per-type handler installed by the builder: at `0x0041E79E` it
  loads `[esi+0x7c]`, null-checks it, builds a stack record containing the
  pool record pointer at `[esp+0x44]`, and executes `call eax` at
  `0x0041E7C7`. This is an outbound register-indirect call and the only found
  edge to the ten handlers in `[0x0041BEF0, 0x0041C2C0]`.
- After the loop, reads the opcode at the just-persisted program counter and,
  through the byte table
  `0x0041E8F4` and jump table `0x0041E8D4`, selects one of five modes for
  opcodes 5, 6, 7, 9, 17, 18 and 20 — seven of the eight opcodes whose
  dispatch entry has no body. Opcode 0 is the eighth; it blocks but lies
  outside the `5..20` window, so it leaves the mode at its initialised `0`.
- Opcode 16 (`0x0041E078`) compares the squared XZ distance between slot
  `+0x04`/`+0x0C` and `0x0059D910`/`0x0059D918` against the operand squared.
- Opcodes 2, 3 and 14 consume bytes through the shared cursor `0x00599C60`.
- Opcode 11 calls one of nine subroutines chosen by its operand, through the
  jump table at `0x0041E8B0`, and is the **only** handler with a range check
  (`dec eax / cmp eax,0x8 / ja` at `0x0041DF4C`-`0x0041DF50`).
- Opcode 13 indexes the 28-entry sequence table with
  `mov eax,[eax*4+0x4c8754]` at `0x0041E01A` using the sign-extended operand
  and **no** bound check. Its 1..24 operand span in the shipped programs is a
  property of the data, not an invariant the code maintains; see `KU-069`.

The complete opcode table, sizes and operand ranges are in
`static/exports/BIN-97c95ba5572dce63/SUBSYS-creature-actor-static-census.md`.

## Inferred

That the no-body opcodes are "states" and the rest are a "program" is a
description of the two dispatches, which are independent in the code and agree
on all but opcode 0. No individual state is given a behaviour name.

## Unknown

What the five modes do; what the nine opcode-11 subroutines do; whether any
program is ever executed at runtime (`KU-068`).

## Later findings (2026-10-18)

- **List selector.** Op 4 and op 10 read the list index from
  `byte [source + 0x0E + ((+0x5C >> 3) & 1)]`. A record type above `0x8000`
  as a word (a negative type) selects the 6-byte relative form from `+0x10`;
  otherwise the 12-byte absolute rows from `+4` are used. Op 10's nonzero
  operand starts the cursor at source `+0x0F` with no count check.
  Every shipped walker's list exists:
  [[EXP-20261018-001 - Creature row index census]].
- **Branches.** Op 8 and op 19 branch to `edi + 2 + operand*2`
  (`0x0041DEA4`–`0x0041DEAC`); op −1 jumps to `edi − operand*2`.
- **KU-068 at runtime.** Saved samples answer "whether any program is ever
  executed":
  - Dot's slot holds only script-7 instruction starts, in the decoded order
    from its first activation.
  - The moved taxi bug's slot holds script 23, and script 13 once dead. Its
    op-4 targets equal its list rows.

  See [[EXP-20261018-002 - Creature script counter in saved runtime samples]].
- **The five modes and the tail** (`0x0041E147`–`0x0041E845`), read in
  [[EXP-20261018-003 - Creature VM movement modes]]:
  - mode 1 steers and accelerates toward the target;
  - mode 2 does so until within source `+0x14 << 4`, then steps past the
    blocking opcode;
  - modes 3 and 4 wait for a ground creature to land;
  - a chase (flag `0x0002`) retargets Flik near home.

  Every frame then applies friction, the leash (source `+0x16 << 4`, from
  home, which op 4 moves to the previous waypoint), gravity or flight
  easing, animation and the type handler. The "Unknown" line above about the
  modes is superseded.
- **Handlers and opcode 11.** The ten per-type handlers and the nine
  subroutines are read in
  [[EXP-20261018-004 - Creature type handlers and opcode-11 subroutines]].
