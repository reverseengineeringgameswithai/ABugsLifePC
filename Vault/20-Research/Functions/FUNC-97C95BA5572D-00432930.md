# Function 0x00432930

## Summary

Conditionally selects a nearest PC type-1 coordinate row, writes scaled X/Z
to the auxiliary/reset-coordinate globals, and recomputes Y. Two natural
Level03 pit events now confirm its bounded reset role; `checkpoint` remains an
unsupported broader semantic name.

## Confirmed

- Tests bit `0x10` in state word `0x0059D9A0` before entering the row scan.
- Reads the relocated type-1 record through pointer slot `0x005C5864`.
- Scans 12-byte signed coordinate rows using squared X/Z distance from
  auxiliary/reset-coordinate globals `0x0059D960` and `0x0059D968` with the
  matching scale shift.
- Writes selected X and Z shifted left by five to those globals and obtains Y
  through the existing terrain-height path before a fixed vertical adjustment.
  EXP-20260816-141 pins the path exactly: `0x0059D964` is set to sentinel
  `0x7FFFFFFF`, thunk `0x00401659 -> 0x004AC460` receives the triple's
  address (push at `0x004329BA`), and actor Y is the returned height
  minus `0x100` (`0x004329F1`). The offline reimplementation reproduces
  the accepted EXP-130 walkable Y 30092 exactly through this relation.
- Level03 row 6 is at file offset `0x4A4` with raw XYZ
  `(15678,0,15438)`. Evidence: [[EXP-20260815-116 - Level03 type-1 row discriminator]].
- The variant at `0x00437A20` is not merely near-identical: the whole
  185-byte selection body `0x00432930-0x004329E8` equals
  `0x00437A20-0x00437AD8` byte for byte, both `call`s resolve to
  `0x00401659`, and the tails match. Only `0x00432930`'s shared exit adds
  `mov edx,[0x0059EFE4]; mov [0x0059EFE8],edx`. The `0x0042DDB0` dispatch on
  `0x00861C84` therefore cannot change which row is selected.
  Evidence: [[EXP-20260816-153 - M5 entry gate and type-1 reset placement resolver]].
- Exact scan arithmetic, from disassembly rather than summary: the row count
  is the **unsigned** word at `record + 0` (`0x0043294A`); the query is
  reduced with `sar 5` (`0x0043296A`, `0x0043296D`) and each difference with
  `sar 3` (`0x00432986`, `0x0043298D`), so negative values round toward
  negative infinity; both squares and their sum are 32-bit and wrap
  (`0x00432990`, `0x00432995`, `0x00432998`); and `0x0043299A`'s `cmp`/`jge`
  keeps only a strictly smaller distance, so the **lowest index wins a tie**.
  Row `i` is at `record + 4 + 12*i` with X at `+0`, an unread middle dword at
  `+4`, and Z at `+8`.
- With a zero row count `0x0043295C` skips the loop and `0x004329B0` still
  reads the best-index local `[esp+0x18]`, which is written only inside the
  loop at `0x004329A0`. The original then indexes the record with stale stack
  data. Two squares sum to 0, 1 or 2 modulo 4 and truncation preserves that
  residue, while the `0x7FFFFFFF` seed is 3 modulo 4, so a non-empty row list
  always selects a row and this is the *only* path to the uninitialised read.
- A failed height query is not an error here: `0x004ACDB2` stores
  `0x80000000` in the query block, `0x004AC6B8` returns it, and
  `0x004329F1` turns it into `0x7FFFFF00`.

## Inferred

The natural Level03 pit evidence supports an authored reset-row selector at
that boundary. Whether the rows are visible checkpoints or share this role in
other levels remains inferred.

## Unknown

The complete state machine, which natural events reach the gate, the
mode/character distinction between the two variants, and whether every level
uses type 1 for the same purpose.

## 2026-08-15 runtime confirmation

EXP-116 confirms this function's Level03 row consumer behavior on PC. With gate bit `0x10` set, it selected nearest type-1 row 6 through live pointer `0x005C5864 = 0x0064AD0F`.

- control row X/Z `(15678, 15438)` became `(501696, 494016)`;
- candidate row X/Z `(15806, 15438)` became `(505792, 494016)`;
- the exact X delta was `+4096 = 128 << 5`;
- Y was recomputed through the terrain helper and is not a direct row-field claim.

The successful arm used disclosed prerequisite-state writes. See [[EXP-20260815-116-receipt]].

## 2026-08-15 approval-compliant row-6 discriminator

[[EXP-20260815-117 - Approved Level03 row-6 reset rerun]] confirms this
consumer after prior explicit authorization of the exact prerequisite writes:

- control row-6 X `15678` produced runtime X `501696`;
- candidate row-6 X `15806` produced runtime X `505792`;
- observed delta `4096` equals `(15806 - 15678) << 5`;
- unchanged row Z `15438` produced `494016` on both sides;
- Y differed because this function's terrain path recomputes it independently.

This supports the descriptive name `Level03 type-1 row reset-coordinate
consumer`. It does not yet support the semantic name `checkpoint loader`.

## 2026-08-15 natural row-7 selection

[[EXP-20260815-129 - Natural Level03 pit material-1 and row-7 reset]] joins
the static selector to ordinary PC behavior. Two entries into the single pit
revealed by the first grain gate produced descriptor/value `572/1`, flags
`0x14`, and `NextLife=2`. Row 7 was nearer than row 6 at both material-contact
samples, and both first sampled post-reset positions were

natural row-6 selection remains unobserved and broader checkpoint semantics
remain unsupported; EXP-131 disposes of both as M3.5 blockers.

## 2026-08-16 engine-exact offline resolver

[[EXP-20260816-153 - M5 entry gate and type-1 reset placement resolver]]
reimplements this selector in `reimplementation/ablpc/type1_reset.py` and
reproduces every retained receipt: both natural EXP-129 pit falls select row 7
and place `(497248, 31176, 547264)`; the EXP-130 walkable point selects row 6
at distance 0 and reproduces Y `30092` exactly; the EXP-116/117 candidate row
reproduces the `+4096` X delta. The model's terrain descriptor 543 at the
row-7 placement independently matches the collision descriptor EXP-129
sampled after the reset.

EXP-129's quoted squared distances (`453,992,741` versus `1,084,822,693`) are
world-unit values, not this function's arithmetic; the engine-exact values at
that contact are `7,010` for row 7 and `16,466` for row 6. The selected row is
unchanged.

Structural, from independent sources: Level03's 18 rows pair one-to-one with
the nine Tunnels grain gates whose centres EXP-136/139 took from executable
immediates — rows `2n` and `2n+1` are the two nearest rows to gate `n` at
13,729-17,993 and 37,231-39,316 units, with the next gate 303,653 units or
more away. The numbers are confirmed; near/far reset pairing is inference and
does not promote `checkpoint` semantics.
