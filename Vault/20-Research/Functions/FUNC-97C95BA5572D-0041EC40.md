# Function 0x0041EC40

## Summary

Per-frame pass over the 64-slot pool at `0x0059B628`. It first rebuilds a
NULL-terminated pointer list of slots within a radius of the camera common
block, then walks that list and advances each selected slot.

## Confirmed

- Iterates the pool with `esi` at slot `+0x6A`, from `0x0059B692`, stepping
  `0x84` at `0x0041ED4F` and ending on `cmp esi,0x59d792` at `0x0041ED55` —
  64 slots, last base `0x0059D6A4`.
- Clears flag bit `0x4000` in `+0x5C` at `0x0041EC63` and sets it at
  `0x0041ECEE` for a selected slot.
- Skips a slot whose `+0x00` is `<= 0` (`0x0041EC6A`) and branches on
  `+0x6E > 0` (`0x0041EC74`).
- Selection test at `0x0041EC7F`-`0x0041ECE1`:

  ```text
  dx = (word[+0x64] - dword[+0x04] + [0x00599C90]) >> 8
  dy = (word[+0x66] - dword[+0x08] + [0x00599C94]) >> 8
  dz = (word[+0x68] - dword[+0x0C] + [0x00599C98]) >> 8
  r  = (word[+0x6A] >> 3) + 0x258
  select when dx*dx + dy*dy + dz*dz < r*r
  ```

  `0x00599C90` is the camera common block accepted in
  `EXP-20260816-165`.
- Appends the slot pointer to the list at `0x0059D7E0` and NULL-terminates it
  at `0x0041ED6A`, then calls `0x00456640` with the camera block.
- Second pass `0x0041ED9A`-`0x0041EEF7` calls `0x00467E60` (thunk
  `0x00401488`), `0x0041D5B0` (thunk `0x0040147E`) or the interpreter
  `0x0041DC60` (thunk `0x004017F8`) depending on `+0x5C` bit `0x20` and
  `+0x6C`, then steps `+0x4A` toward zero and calls `0x0041B9F0(slot, 1)` when
  it reaches zero and `0x0041B9F0(slot, 2)` on the removal path.

## Inferred

The first pass is a proximity cull: the arithmetic is a squared-distance test
against a per-slot radius, but nothing here proves what "selected" is used
for beyond the second pass.

## Unknown

What `0x00456640` does with the list; what `0x0041D5B0` does; the meanings of
`+0x64`/`+0x66`/`+0x68` as distinct from the slot position.

## Later findings (2026-10-18)

- **The interpreter gate.** In the second pass, `0x0041EDA2` sends a slot
  with bit `0x20` to the seed arm, which never calls the interpreter. With
  the bit clear, `0x0041EE89`–`0x0041EE9C` calls it when bit `0x0001` is
  set, when source `+0x11` is not `0x64`, or for type 15. Otherwise it skips
  the call.
  - Bit `0x0001` is the visibility bit that `0x00456640` recomputes at
    `0x0041ED75`, just before this pass
    ([[EXP-20261012-004 - Homing target visibility bit]]). That answers
    "what `0x00456640` does" above.
  - So regular enemies (`+0x11 = 100`) think only on screen, and the 130
    seed rows never do.
  - `0x0041EE9F` is the interpreter's only call site (Ghidra export and a
    raw image scan): [[EXP-20261018-001 - Creature row index census]].
- **A derived-build hook.** Six bytes at `0x0041EDB4`, on the seed arm,
  differ in project EXEs `0480e36b…`, `3d02de3a…` and `c3d8b207…`
  (EXP-20260908-001). The interpreter path is unchanged:
  [[EXP-20261018-002 - Creature script counter in saved runtime samples]].
