# Function 0x0044BB70

## Summary

Walks and relocates sections in a complete `LEVEL*.DAT` file whose allocated-buffer pointer is stored in global `0x005BA240`. The caller at `0x004671D0` supplies an internal level value and the byte length returned by `0x004AE240`.

## Confirmed

- Walk rules and section boundaries are described in [[PC LEVEL DAT prefix]]. Evidence: static export at `0x0044BB70` and 21-file corpus parse in `EXP-20260812-006`.
- The dword at 20-byte record offset `+0x10` is converted from file-relative offset to memory pointer for active records. Evidence: decompiler at `0x0044BB70`.
- The final file dword is consulted as a backward distance unless it is `-1`. Evidence: decompiler at `0x0044BB70`.
- In `RUN-GDB-20260812-021920`, `*(uint32_t *)0x005BA240` was `0x006590D7`; record and payload addresses matched `base + file_offset`. This corrects the earlier ambiguous description of `0x005BA240` as the loaded “base.”
- The observed primary-record pointer `0x00659587` was exactly `base+0x04B0`, independently matching the parser's primary section boundary. Evidence: [[EXP-20260812-008 - Training record watchpoints and individual roles]].
- Scene flag bit `0x08` selects payload target field `+0x1C`; otherwise the field is `+0x14`. Flag bit `0x20` additionally relocates `+0x20` or `+0x18`. Exact instructions: `0x0044BD03–0x0044BD73`, [[EXP-20260812-009 - Training payload target structure and reuse census]].
- Indexes each top record by signed type into the 64-pointer table rooted at
  `0x005C5860`. A nonnegative type is written at `0x0044BCA9`; type `0x3F`
  uses the special `4 + count*16` stride. Slot 63 is `0x005C595C`, read by
  `0x00416100` to derive plant resource IDs. Evidence:
  [[EXP-20260812-016 - Plant request origin and separate DAT table]].
- A **negative** type is stored too, at `0x0044BC8B-0x0044BC95`: `edx` holds
  the sign-extended type times four and the code computes
  `0x005C5860 - edx`, so type `-N` **aliases into the same slot as type
  `+N`** even though its elements use the `0x10`-header/6-byte form advanced
  at `0x0044BC97-0x0044BCA3`. The walk overwrites, so the **last** record
  claiming a slot is the one a consumer sees. No retail `LEVEL*.DAT` exercises
  either case for the type-1 slot; both are covered synthetically. Evidence:
  [[EXP-20260816-153 - M5 entry gate and type-1 reset placement resolver]],
  file offsets `0x04B08B` and `0x04B0A9`.

## Inferred

The function is a level-DAT fixup routine. Stronger semantic names for individual sections are not established.

## Unknown

Meaning of the internal level argument, most top-record types and fields,
non-target suffix sections, negative-count target blocks, and most relocated
payload fields. Type `0x3F` participates in plant resource selection, but its
complete semantics remain unknown.
