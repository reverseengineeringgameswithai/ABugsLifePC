# Function 0x0042EBC0

## Summary

Reads DirectInput keyboard and joystick-0 state and reduces it to one
action-bit word at `0x00598B10` plus a synthesised two-axis value.

**Extent:** code `0x0042EBC0`-`0x0042EEBB` (file `0x02DFC0`-`0x02E2BB`), one
`ret` at `0x0042EEBB`, followed by its own jump table at `0x0042EEBC` and byte
table at `0x0042EED0`, then `nop` padding from `0x0042EF41`. Every target in
that jump table lies inside the code range, so nothing after the `ret` is
separately entered.

## Confirmed

- Gates on `[0x00598BC8]`; zeroes `0x00598B10`, `0x00598B12`, `0x00598BC0`,
  `0x00598BC2`, `0x00598BC4`, `0x00598BC6`, `0x00598B5C`.
- Clears 256 bytes at `0x00598A10`, then `Acquire` (`+0x1C`) at `0x0042EC1C`
  and `GetDeviceState(0x100, 0x00598A10)` (`+0x24`) at `0x0042EC31`. A key is
  `0x00598A10 + scancode`.
- Folds right modifiers onto left: `0x36 → 0x2A`, `0x9D → 0x1D`,
  `0xB8 → 0x38`.
- Walks twelve 8-byte entries over `[0x004D8430, 0x004D8490)` at
  `0x0042EC86`-`0x0042ECDF`, ORing each pressed key's mask; result stored to
  `0x00598B10` at `0x0042ECE3`. `DIK_TAB` is special-cased just before the
  loop and uses the mask slot `0x004D8474`.
- Masks in `[0x10, 0x80]` steer a five-arm switch (byte table `0x0042EED0`,
  jump table `0x0042EEBC`) that adds or subtracts `0x8000` in `edx`/`ebp`;
  those are stored to `0x004F0444` and `0x004F0440` at
  `0x0042ECEC`-`0x0042ECF2`. Only the four direction masks qualify.
- Joystick 0, gated on `[0x00598B28]`: `Poll` (`+0x64`) at `0x0042ED0E`,
  `Acquire` on failure, `GetDeviceState(0x50, 0x00598B60)` (`+0x24`) at
  `0x0042ED2F`, `Acquire` on failure. A second accumulator is ORed from
  `[esi*8+0x004D8434]` at `0x0042EE9D`.
- Buttons: the eight-iteration loop `0x0042ED6F`-`0x0042ED8C` walks
  `[0x004D8490, 0x004D84D0)` and tests `[esi + 0x00598B90]`, where `esi` is
  each pair's first column and `0x00598B90 = 0x00598B60 + 0x30` is
  `DIJOYSTATE.rgbButtons`. This makes the first column a button index by
  instruction, not by inference.
- The axis store at `0x0042ECEC`-`0x0042ECF2` is guarded by `edi`, set at
  `0x0042ECA0` for **any** pressed binding entry — not only a direction.

## Later findings (2026-10-02 audit pointer)

- "Dynamic evidence: None" is superseded.
  [[EXP-20260817-187 - Runtime berry throw reconnaissance]] sampled
  `0x00598B10` at runtime (retail `97c95ba5…`): holding Ctrl gave `0x8000` in
  248 samples, matching the static `DIK_LCONTROL` → `0x8000` binding; `0x0040`
  and `0x0020` appeared from movement. That is the read-only sample the
  experiment below asked for, for one bit. Other bits stay under `KU-070`.
- Caller `0x00464E1C` is inside the input latch `0x00464E10`–`0x00464E2F`. It
  copies `0x00861C98` to `0x00861C8C`, calls this function, then stores
  `0x00598B10` to `0x00861C98` (EXP-20260817-187; rechecked by disassembly
  2026-10-02). So `0x00861C98` is one consumer of the action word.
- EXP-20261001-003
  uses a new press of mask `0x8200` (default `DIK_Z` and joystick button 3)
  through that latch in hardware. Caller `0x0049BDB7` is still unanalysed.
