# Function 0x004ADC30

## Summary

Records the current directory, checks whether the current drive is a CD-ROM, otherwise scans drive letters `C:` through `Z:`, and records the first drive reported as `DRIVE_CDROM`.

## Confirmed

- Calls `GetCurrentDirectoryA` and logs `LOADING : App run from %s.`. Evidence: `EXP-20260811-004`, address `0x004ADC30`.
- Calls `GetDriveTypeA(NULL)` and accepts return value 5. Evidence: `EXP-20260811-004`, xref `0x004ADC73`.
- If the current drive is not accepted, constructs roots from `C:\` through `Z:\` and calls `GetDriveTypeA` until a return value of 5 is found. Evidence: `EXP-20260811-004`, xref `0x004ADD0F` and loop control.
- Stops at the first accepted CD-ROM drive without checking game-disc content. Evidence: `EXP-20260811-004`, control flow.
- Logs `LOADING : No CD-ROM found.` when no drive qualifies. Evidence: static string and `RUN-WINE-20260811-233536-GAME-LOG`.
- Under the current Wine directory-backed `R:` mapping, the game reported no CD-ROM and used the current-directory fallback. Evidence: `RUN-WINE-20260811-233536-GAME-LOG`.

## Inferred

- Global `0x00861F14` selects between current-directory and CD-root loading modes.
- Global buffer `0x00861E80` stores the selected CD root.
- The first-CD behavior can select the wrong optical drive on a multi-CD system; this follows from confirmed control flow but has not been reproduced dynamically.

## Unknown

- Why Wine's `R:` registry type override did not produce an accepted return value in the game.
- Behavior with a real physical optical drive or loop-mounted ISO block device.
- Whether the retail installer normally relies on current-directory fallback.

- [[86Box Win95 RE harness]] (Gotcha 6; session
  [[2026-08-18 0330 - Claude - Win95 and A Bug's Life installed in 86Box]]):
  under emulated Windows 95 with retail `97c95ba5…`, a detected CD-ROM drive
  gave `LOADING : Files will be loaded off D:.` and a fatal failed
  `D:\pc\bugs\cd\cd.txt` read, with no fallback. Without a CD drive the
  game used `C:\PC\BUGS\CD\CD.TXT`. This is runtime evidence for the
  CD-root branch: an accepted drive is used even when its read fails.

  CD-root load, a multi-drive system and the Wine block-device case remain
  untested.
