# Function 0x0042DB10

## Summary

Registers a 60-byte event record into slot `id` of the 16-slot table at
`0x005982B0`, destroying any current occupant first and calling the new
record's create callback last.

**Extent:** `0x0042DB10`-`0x0042DC46` (file `0x02CF10`-`0x02D046`). One `ret`,
at `0x0042DC46`, followed by `nop` padding. Every direct branch inside the
range was enumerated; the only outbound target is `0x00401CF8`.

## Confirmed

- Reads the id with `movsx eax,WORD PTR [ebx]` at `0x0042DB18` — a **signed**
  word — and scales it by `0x3C` throughout, with **no bounds check** between
  the read and the first access at `0x0042DB26`.
- If `[+0x34] != 0` at `0x0042DB26`: when `[+0x0C]` is non-null, logs
  `0x004D8264` and calls it at `0x0042DB67`; then zeroes `+0x34`, `+0x38`,
  `+0x30`, `+0x02`, `+0x32`, `+0x04`, `+0x08`, `+0x0C` — every field except the
  **id** at `+0x00` and the **name** at `+0x10`, neither of which any clearing
  path in this subsystem writes — over `0x0042DB83`-`0x0042DBB0`, and *then*
  logs `0x004D830C` at `0x0042DBB6`. The order is zero-then-log, not
  log-then-zero. The name that log line prints is the **caller's**
  (`lea edx,[ebx+0x10]` at `0x0042DB71`), not the table record's.
- Copies 15 dwords from the caller's record to `[eax*4+0x5982b0]` at
  `0x0042DBCE`-`0x0042DBD5`.
- Sets `[+0x34] = 1` at `0x0042DBE0`.
- If `[+0x04]` is non-null, logs `0x004D82CC` and calls it at `0x0042DC2A`.
- Logs `0x004D82A4` at `0x0042DC35`.

## Inferred

Nothing. That `0x004ADEA0` writes a log file is confirmed by a named import —
it reaches `KERNEL32.dll!DeleteFileA` with `"bugs.log"` via the wrapper
`0x004B13E0`. The fopen/fprintf/fclose roles of `0x004B0730`, `0x004B13A0` and
`0x004B04E0` are undecoded, but nothing here depends on them.

## Callers

`0x004D81A8`, the `"WINDOWS"` record) and `0x0043DB10` (pushing `0x004D81E8`,
the `"DIRECTX"` record). Their enclosing function was not analysed.

## Callees

Thunk `0x00401CF8` → `0x004ADEA0`, which writes the log file `"bugs.log"`
(reaching `KERNEL32.dll!DeleteFileA` through `0x004B13E0`, one-shot behind
`0x004E9170`, then opening in mode `"at"`) from a `0x400`-byte stack buffer
filled by `0x004B0150`. Its body is gated on `0x008620AC`. Plus the record's own
`+0x04` and `+0x0C` callbacks through indirect `call`.
