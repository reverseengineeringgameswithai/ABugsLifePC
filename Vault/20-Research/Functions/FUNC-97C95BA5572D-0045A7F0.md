# Function 0x0045A7F0

## Summary

Consumes a payload target block, transforms referenced 12-byte table entries,
and builds native-software or Direct3D renderer output from a command stream.

## Confirmed

- `0x0045A7FF` loads the first argument and `0x0045A81E` establishes the table
  base four bytes later.
- `0x0045A82E` reads a signed count. For a nonnegative count,
  `0x0045A897–0x0045A89E` advances by `count × 12` bytes to the command stream.
- The command loop tests for the `0xFFFF` terminator at `0x0045A8B0`.
- A command header contains a mode word and signed item count. The low mode bit
  selects a 16-byte or 12-byte item path.
- Command items contain 16-bit offsets into the 12-byte table. The function
  transforms referenced values and emits renderer vertices/primitives through
  paths selected by `DAT_0059F7F0`.
- Exact selector mapping is value 1 for native software and value 2 for
  Direct3D. Value-1 paths write the `0x80`-stride software arena; value-2
  paths append to Direct3D batch storage rooted through
  `0x004C4108/0x004C410C` and can flush through
  `0x004056A0/0x004058D0` to the device `DrawIndexedPrimitive` vtable slot.
- Selector 2 is checked at `0x0045A946-0x0045A955` for 12-byte command items
  and at `0x0045C7FB-0x0045C80A` for 16-byte items. The function fills its
  Direct3D batches inline through ten allocation arms; it does not call
  `0x00405FE0` or `0x00407450`.
- In the exact M1 `0x49` route, the second formal argument is unused, the
  third derives from a literal-zero caller input plus `8 * payload[+0x18]`,
  and the fourth is fixed address `0x005BDB9C`. Page/list choice, target-table
  offsets, packed values, transformation state, scratch, batch roots, and
  flush arguments account for every selector-2 builder-facing input.
- The complete selector-2 slice has zero direct references to ID-zero header
  `0x005B18E0` or retained range `[0x005A9660,0x005A9DE0)`, and native
  provenance tracing finds no indirect edge through the exact M1 arguments or
  inline batch inputs (`EXP-20260813-050`).
- The negative-count branch has a distinct layout and temporarily changes the
  sign stored at the target address.

Evidence: exact executable disassembly, Ghidra export, the fully adjacent
Training block population, and same-dispatch corpus validation in
[[EXP-20260812-009 - Training payload target structure and reuse census]].

## Inferred

This is a payload-target renderer, and positive-count blocks contain reusable
geometry-like content. These names do not establish exact table fields,
primitive types, materials, or a complete object-definition boundary.

## Unknown

- Negative-count block layout and mutation lifetime.
- Exact meanings of command mode bits and item suffix bytes.
- Exact field-level differences between software and Direct3D consumption.
- Whether animation or other state can select different visible output from
  one target block.
