# Function 0x004498F0

## Summary

Consumes arrays of selected 20-byte scene records, masks their flags to choose
a dispatch path, applies placement/payload transforms, and calls downstream
rendering functions.

## Confirmed

- `0x00449919` loads a scene-record pointer from the input array and
  `0x0044991F` reads its word at `+0x0E`.
- `0x00449933` masks the flags with `0xBFEF` before a jump-table dispatch.
- Training flags `0x0059` select masked value `0x49`.
- In the corresponding decompiler case `9/0x49`, the function replaces the
  record with its payload pointer at record `+0x10`, reads payload `+0x1C` at
  `0x00449E1A`, and calls thunk `0x00401604` at `0x00449E20`.
- Thunk `0x00401604` jumps directly to `0x0045A7F0`.

Evidence: exact executable disassembly and Ghidra export in
[[EXP-20260812-009 - Training payload target structure and reuse census]].

## Inferred

This is a scene-record rendering dispatcher. Individual flag meanings and the
semantics of most payload fields remain unknown.

## Unknown

- Meanings of dispatch values other than the bounded `0x49` path.
- Exact transform, color, animation, and resource fields in each payload class.
- Whether the same function handles every visible use of a scene record.

## Dynamic evidence

`EXP-20260812-008` confirms that Training records 124–126 are visibly distinct
placements and reach the upstream selection path in `0x0044D430`. No direct
runtime breakpoint or watchpoint at `0x004498F0` is claimed.
`EXP-20260812-010` independently corroborates the bounded dispatch path:
changing only the target passed onward for records 124 or 125 changes only the
corresponding visible placement in phase-matched Direct3D output.

`EXP-20260812-011` bounds the placement input more precisely. In case `0x49`,
`0x00449B61` replaces the selected record pointer with relocated record
`+0x10`; the dwords read at `0x00449B71`, `0x00449B85`, and `0x00449B95` are
payload fields, not record `+0x00`/`+0x04`/`+0x08`. Those record fields act in
the upstream candidate selection instead.

`EXP-20260812-021` directly watchpoints record `+0x10` for Training records
124–126. Each stops immediately after `0x00449B61` with its expected live
record/payload pair. Hardware watchpoints then find no read of plant 10's ANM
slot or two entry `+0x20` dwords before the corresponding `0x00449E25`
target-renderer return. This is limited to those exact destinations/windows.

`EXP-20260813-035` independently confirms statically that this function has no
direct reference to ID-zero slot `0x005B18E0` or retained shared-entry range
`[0x005A9660,0x005A9DE0)` and no call to first-use functions
`0x00402DC0/0x00445FF0`. This is a direct-edge negative for one normal update,
not a lifetime or copied-state claim.

`EXP-20260813-036` shows that the positive-target source walk remains distinct
from retained entry `+0x20`, but downstream `0x0045A7F0` converges with
`0x0044F8E0` on the same conditional output arena and list-root topology.
`EXP-20260813-038` finds that arena inactive during exact Direct3D retained-
entry calls; it does not dynamically test this dispatch. This is static
shared output topology, not active renderer ownership or record-to-resource
identity.
